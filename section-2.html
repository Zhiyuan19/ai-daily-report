扩展的工具包：为什么你的脚手架正在融入模型

来源： @Anthropic/Code with Claude 大会 | 评分：91 | 发布时间：2026-05-08 20:21 GMT

核心观点：

开发者过去为提高 LLM 可靠性而构建的复杂基础设施（工具路由器、重试循环、上下文管理系统）正被模型原生 API 直接吸收。核心建议：停止弥补模型的不足，转而专注于将模型连接到独特的专有数据。

深度摘要：

在 Code with Claude 大会上，Anthropic 的研究产品经理 Lucas 发表了题为"扩展的工具包"（Expanded Toolkit）的演讲，系统性地梳理了 LLM 技术演进的四个关键领域及其对开发者实践的影响。

工具使用（Tool Use）的范式转变：Lucas 指出，当前的模型已实现"自主工具选择"——模型不再依赖外部路由器来决定调用哪个工具，而是原生理解工具语义并主动选择。这一转变的核心意义在于：过去开发者为解决"模型不知道该用哪个工具"问题而构建的复杂路由器（Router），如今反而成为性能瓶颈。Anthropic 的内部数据显示，在工具选择准确性已经足够高的当下，路由器和预过滤机制平均降低任务成功率 8-12%。

上下文管理的简化：100 万 token 的上下文窗口配合服务端压缩技术（Server-side Context Compression），大幅降低了对复杂 RAG 管道的需求。开发者不再需要精心设计向量检索策略、实体链（Entity Chain）或知识图谱——模型可以直接在上下文窗口内完成对大量长文本的语义理解和精确问答。Lucas 强调，这一变化正在使过去 6-12 个月搭建的 RAG 系统"快速过时"。

代码执行与计算机使用：托管沙盒（Managed Sandboxes）允许模型在一次 API 调用中完成"编写→运行→修复"的完整闭环，原生高分辨率屏幕理解（1440p）使 UI 自动化不再需要手动坐标映射。这两个能力加在一起，将传统自动化脚本需要解决的核心工程问题全部吸收进 API 层。

核心结论：演讲者提出"代码半衰期"（Code Half-life）概念——为弥补模型不可靠性而编写的代码，半衰期只有数月。以规划器（Planner）、验证循环（Validation Loop）、重试逻辑（Retry Logic）为例，这些组件的生命周期与特定模型能力绑定，随着模型能力增强，同类问题的解决方案会直接进入模型层，这些代码将成为无人维护的技术债务。

最持久的开发投入方向是连接层代码——将模型与专有数据、自定义工具、特定业务逻辑绑定的代码。这类代码产生"复利效应"：模型无法吸收它看不到的信息，连接层沉淀的业务知识具有独占性。

Asana 如何利用 Claude Managed Agents 构建「多人协作」AI 队友

来源： @Asana | 评分：93 | 发布时间：2026-05-08 18:50 GMT

核心观点：

Asana 正在将 AI Agent 从"单人模式"升级为"多人协作模式"——让 AI 智能体作为真正的团队成员参与协作，共享任务上下文、共同完成任务分解与执行。

深度摘要：

Asana 在 Code with Claude 活动上披露了其"智能体企业"（Agentic Enterprise）的愿景与实现路径。这套系统的核心是 Asana 积累 17 年的 Workgraph——一个理解组织目标、项目节点、任务依赖、历史决策的深层上下文图谱。与简单的任务列表不同，Workgraph 将组织内每个任务还原到"谁负责、依赖谁、为何此时做、以往如何处理类似问题"的完整关系网络中。

Asana 在此基础上利用 Claude 的 Managed Agents 构建 AI 队友。每个 AI 队友有明确的责任范围（Scope of Responsibility），可以主动发起子任务、向上级汇报进展、向平级请求协作。在演示中，一个"代码审查 AI 队友"可以主动从 Asana 读取 PR 信息、调用 GitHub API 拉取变更内容、执行静态分析、将审查意见写入 PR 评论，并同步结果到相关开发者的 Asana 任务列表——整个流程无需人工触发。

技术实现上，Asana 为每个 AI 角色配置了特定的工具权限集合（Tool Permission Scope），确保 AI 行为边界与人类团队成员的角色边界一致。同时，Asana 引入了"人类审计节点"（Human-in-the-loop Checkpoints），在关键决策点（如发送外部邮件、删除数据、批准高风险操作）强制人工确认。

这一架构的深层意义在于：它重新定义了"AI 在组织中的位置"——不再是工具，而是有角色、有权限、有责任的团队成员。

工具选择已足够好：为什么路由器正在伤害你的 Agent

来源： @Anthropic 技术博客 | 评分：90 | 发布时间：2026-05-08 14:30 GMT

核心观点：

随着模型原生工具选择能力大幅提升，传统外部路由器（External Router）反而开始成为性能瓶颈和错误放大器。架构精简已成 Agent 开发新趋势。

深度摘要：

这篇文章来自 Anthropic 的内部工程团队，基于对生产级 Agent 系统的长期观测。核心发现是：在 2024-2025 年，开发者普遍通过构建外部路由器来解决"模型工具选择不可靠"的问题——用额外的分类模型或规则引擎预先过滤可调用的工具集，只将相关工具子集传给主模型。这一做法在模型能力相对较弱的阶段是有效的工程折中。

但进入 2026 年后，以 Claude 3.7+ 为代表的模型已原生实现了准确率高于 95% 的工具选择能力。在此背景下，外部路由器的负面效果开始显现：

  • 信息损失：预过滤不可避免地排除了一些"看起来不相关但实际关键"的工具，导致模型在需要特定工具时无工具可用
  • 延迟增加：每次工具调用多经过一层路由决策，平均增加 200-400ms 延迟
  • 维护负担：路由器本身需要持续更新以适配新工具和新场景，形成了额外的技术债务

文章给出的建议是：如果你的 Agent 在 2025 年搭建了外部路由器，现在应该测试移除它，用模型原生的工具选择能力直接替代。Anthropic 在多个生产系统的测试数据显示，移除路由器后任务完成率平均提升 6-14%，延迟降低 15-25%。

对于确实需要路由的场景（超过 50+ 工具的超大型工具集），建议采用"语义聚类"而非"分类路由"：将工具按功能语义分组，模型只需选择工具组而非单个工具，再在组内进行细粒度选择。
