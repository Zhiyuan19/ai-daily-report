nanobot — 超轻量级个人 AI Agent

一句话描述：香港大学数据科学实验室出品，保持核心 Agent Loop 极简可读的同时支持多渠道聊天、记忆、MCP 的个人 AI Agent。

背景与原理： nanobot 由香港大学数据科学实验室（HKUDS）开发，定位为 OpenClaw、Claude Code 和 Codex 的"轻量化替代"。项目采用极简核心循环设计，将 Agent 的规划-执行-验证链路压缩到最小可维护单元，避免了主流 Agent 框架的过度工程化问题。核心技术架构包括：基于语义向量的记忆系统（每轮对话将用户/助手消息嵌入为向量，检索时做余弦相似度匹配）、跨平台聊天通道抽象层（支持飞书、Discord、Slack、Teams 等）、MCP（Model Context Protocol）工具生态，以及可选的 Dream 技能自动发现机制。最新版本 v0.1.5.post3 于 2026年4月29日发布，新增 Feishu/Discord/Slack/Teams 线程智能化和 DeepSeek-V4 支持。

核心创新点： - 轻量内存开销：单会话仅 167MB（含 embedding），竞品 Claude Code 为 386MB，OpenCode 为 371MB，差距达 2-13 倍 - 启动速度：首次响应帧时间 14ms，Claude Code 为 3436ms，相差 245 倍 - 多会话线性扩展：每新增一个活跃会话仅增加 ~10.4MB，竞品增加 76-318MB - 开放工具支持：集成 DeepSeek、Kimi、MiniMax 等国产模型渠道；支持 OpenAI Reasoning 自动路由与 Responses 降级

实际意义： nanobot 为个人开发者提供了真正可在本地长期运行的 AI Agent 方案，无需订阅闭源服务即可获得记忆持续、多渠道接入、工具扩展的能力组合。对比同类产品，nanobot 在树莓派级别硬件或低配云服务器上均可流畅运行，有望成为边缘 AI 和隐私敏感场景的首选基础设施。

取得的突破： - 单会话 RAM 占用 167MB（同类最低） - 首次响应延迟 14ms，远超所有主流 Agent - 2026年4月连续每日更新，已支持 12+ 渠道平台 - GitHub Stars: ~41.3k，本周持续增长

链接： https://github.com/HKUDS/nanobot

jcode — 下一代 Coding Agent Harness

一句话描述：Rust 编写的高性能 Coding Agent 开发框架，以极低资源开销支持多会话工作流与无限可定制化。

背景与原理： jcode 由开发者 1jehuang（Build by @claude）构建，定位为"提升 Coding Agent 技能天花板"的下一代 Harness。与传统 Agent 框架在每次交互时重新构建上下文不同，jcode 将每轮用户-助手对话嵌入为语义向量，存入本地向量图数据库；检索时通过余弦相似度匹配历史记忆，将相关内容注入当前对话上下文，从而实现接近人类的"主动回忆"能力，无需显式调用记忆工具。其核心性能优势源于 Rust 的零成本抽象和高效的内存布局，所有性能指标均为自主研发而非依赖第三方抽象层。

核心创新点： - 超低 RAM 消耗：单会话 167MB（含 embedding），多会话线性增长仅 ~10.4MB/session - 极速启动：首次输入延迟 48.7ms，Codex CLI 为 905ms，Claude Code 为 3512ms - 记忆系统原生化：将 RAG 记忆作为后台能力而非显式工具调用，降低 Agent 认知负荷 - 跨模型兼容：支持 Claude、GPT-4、Codex、Gemini 等主流模型的自适应路由

实际意义： jcode 的出现填补了"低资源+高性能+Coding Agent"交叉点的空白。传统 Agent 框架（如 LangChain、AutoGen）在复杂多会话场景下资源开销呈指数增长，而 jcode 通过 Rust + 图记忆的协同设计，首次在该赛道实现了性能与可维护性的平衡。对算力受限的独立开发者或边缘部署场景具有重要参考价值。

取得的突破： - 多会话场景 RAM 效率：jcode 117MB vs OpenCode 3237MB（27.7倍差距） - Boot 速度：14ms vs Claude Code 3436ms（245倍差距） - 2026年4月29日当日增长 386 Stars

链接： https://github.com/1jehuang/jcode

ds2api — DeepSeek to API 全栈中间件

一句话描述：Go 语言编写的高性能中间件，将 DeepSeek Web 对话能力转换为 OpenAI / Claude / Gemini 兼容 API，支持多账号轮询与工具调用适配。

背景与原理： ds2api 由独立开发者 CJackHwang 构建，采用 Go 语言实现全量后端逻辑，React 前端提供 WebUI 管理控制台。其核心设计思路是将 DeepSeek 的 Web 对话能力（Chat/Responses Runtime、文件上传、工具调用）通过 Prompt 适配层（PromptCompat）转换为各平台的 API 格式差异抹平。架构上采用模块化 chi 路由 + 中间件层（RequestID/RealIP/Logger/Recoverer/CORS），支持账号池 + 队列的并发槽位管理，并通过纯 Go 实现的 PoW（工作量证明）机制防止 API 滥用。前端静态资源在部署时自动构建到二进制中，真正实现零依赖交付。

核心创新点： - 三平台统一接口：同时暴露 OpenAI /v1/chat/completions、Claude /anthropic/*、Gemini /v1beta/models/* 三套接口 - 多账号轮询：内置账号池与请求队列，支持高并发场景下的自动切换与限流 - 工具调用语义对齐：Go/Node 层完成 OpenAI Tool Call 格式到 DeepSeek 工具描述的双向转换 - 零平台依赖：提供预编译二进制（Linux/macOS/Windows）、Docker、Vercel Serverless 三种部署方式

实际意义： ds2api 解决了 DeepSeek API 官方暂不支持部分平台 SDK 的痛点，使开发者可以在不修改业务代码的前提下，将现有的 OpenAI/Claude SDK 无缝切换至 DeepSeek 后端。对需要混合使用多个模型供应商的企业级应用具有重要实用价值。

取得的突破： - 2026年4月29日 GitHub Trending，当日增长 461 Stars - GitHub Stars: 2.7k，Star/Fork 比接近 4:1（高质量项目特征） - 支持 Tool Call + 流式 SSE，完整保留 Agent 能力链

链接： https://github.com/CJackHwang/ds2api

CodeBurn — AI 编程 Token 消费仪表盘

一句话描述：开源 TUI 工具，跟踪 Claude Code、Codex、Cursor 等 16 款 AI 编程工具的 Token 消耗与成本，支持本地离线分析。

背景与原理： CodeBurn 由 AgentSeal 团队开发，是目前支持 AI 编程工具种类最全的本地 Token 追踪工具。其工作原理是直接读取各工具在本地磁盘的会话数据文件（Session JSON/SQLite），配合 LiteLLM 定价表在本地完成费用计算，全程无需 API Key、不走任何代理。支持的工具覆盖 Claude Code、Claude Desktop、Codex、Cursor、Cursor Agent、GitHub Copilot、OpenClaw、Pi、Kiro、OpenCode、Gemini CLI、Droid、Roo Code、KiloCode、Qwen 等 16 款主流 AI 编程产品，涵盖从 VS Code 插件到独立 CLI 的完整生态。

核心创新点： - 完全本地运行：不发送任何数据，不依赖外部 API，数据全部从本地会话文件读取 - 最全工具支持：覆盖 16 款 AI 编程工具，竞品通常只支持 2-4 款 - 交互式 TUI：Arrow 键切换时间维度（Today/7Days/30Days/Month/All），q 退出，c 打开模型对比，o 打开优化建议 - Yield 追踪：量化"有效产出 Token"与"被回退/放弃 Token"比例，帮助识别浪费

实际意义： 随着 AI 编程工具在团队中的普及，成本透明度成为工程管理的新需求。CodeBurn 让开发者无需公司 IT 介入即可了解个人/团队的 AI 工具消费结构，识别异常消耗，并为成本优化决策提供数据基础。

取得的突破： - 2026年4月25日发布 v0.9.1（新增 yield 命令） - GitHub Stars: 4.1k，持续维护中 - 支持 CSV/JSON 导出，便于接入内部账单系统

链接： https://github.com/getagentseal/codeburn

GhostTrack — OSINT 定位追踪工具

一句话描述：Python 编写的开源情报工具，支持 IP 地址追踪、电话号码查询和社交媒体用户名检索。

背景与原理： GhostTrack 由安全研究者 HunxByts 和 bakaemon 构建，是一款面向信息安全研究人员的开源情报（OSINT）工具集。工具提供三大核心功能模块：IP 追踪（通过 IP 定位获取目标地理位置，可与 Seeker 工具联动进行深度信息挖掘）、电话号码检索（从公开数据源查询电话号码关联信息）、用户名追踪（跨 3000+ 社交媒体平台进行用户名枚举）。最新版本 2.2 已发布，依赖 Python3 + 主流 OSINT 数据源 API。

核心创新点： - 一站式 OSINT 套件：整合 IP/电话/用户名三大情报收集维度，无需切换多工具 - 社交媒体广度：覆盖全球 3000+ 平台的用户名枚举能力 - 协同作战：IP 追踪与 Seeker 工具联动，实现"定位 -> 深度挖掘"的链式情报收集

实际意义： GhostTrack 为安全研究人员、渗透测试工程师和事件响应人员提供了标准化的开源情报收集工具，降低了 OSINT 入行门槛，同时也对安全审计和漏洞情报收集具有实际应用价值。

取得的突破： - 2026年4月29日 GitHub Trending，当日增长 1,036 Stars - GitHub Stars: 11.5k，Forks 1.5k - V2.2 版本更新，刚完成重大功能迭代

链接： https://github.com/HunxByts/GhostTrack
